## Writing a plan

A plan describes intent. It may reference files that do not exist yet — that is
the point of a plan — but it **must say so in a status banner at the top**, so a
reader can tell design from description.

When a plan is delivered, update its banner and link the resulting code from
[Architecture Overview](../docs/architecture/overview.md).

For decisions rather than designs, write an
[ADR](../docs/architecture/decisions/README.md) instead.
