## Field Explanations

### 1. **setup_script**

**Purpose**: Prepare fresh worktree for development

**Command**: `composer install && npm install && php artisan key:generate && php artisan migrate`

**Breakdown**:
1. `composer install` - Installs Laravel and PHP dependencies (vendor/)
2. `npm install` - Installs frontend dependencies (node_modules/)
3. `php artisan key:generate` - Generates application encryption key in .env
4. `php artisan migrate` - Runs database migrations to set up schema

**Why these commands**:
- Laravel projects require composer for backend dependencies
- Vite/Tailwind/Alpine.js require npm for frontend tooling
- Laravel requires APP_KEY for encryption (automatically set by key:generate)
- Database schema needs migrations to be functional

**Execution time**: ~2-3 minutes (depending on internet speed)

---

### 2. **dev_script**

**Purpose**: Start development server for live preview

**Command**: `php artisan serve`

**Details**:
- Starts Laravel development server on `http://localhost:8000`
- Hot-reloads PHP changes automatically
- Suitable for development (not production)

**Why not include `npm run dev`**:
- Vite asset compilation runs in background (managed separately)
- Multiple servers can run concurrently
- Each worktree can have independent Vite process

**Alternative access**: Users can run `npm run dev` separately for hot-reloading assets

---

### 3. **verification_script**

**Purpose**: Run linting and tests after each agent turn

**Command**: `vendor\bin\pint && php artisan test`

**Breakdown**:
1. `vendor\bin\pint` - Laravel Pint (code formatter based on PHP-CS-Fixer)
   - Checks code style compliance
   - Ensures PSR-12 standards
   - Fixes formatting issues automatically

2. `php artisan test` - PHPUnit/Pest test suite
   - Runs feature tests
   - Runs unit tests
   - Validates functionality

**Why these checks**:
- **From composer.json analysis**: Project has both "pint" and "test" scripts configured
- **No pre-commit hooks found**: No `.pre-commit-config.yaml` or `.husky/` directory
- **Fast execution**: Both tools typically run in under 60 seconds for this project size
- **Essential for code quality**: Catches bugs and style issues early

**What was excluded**:
- Build steps (too slow, not necessary for verification)
- E2E tests (if any, would exceed 60-second constraint)
- Type checking (not configured in package.json)

---

### 4. **copy_files**

**Purpose**: Copy local configuration files from main worktree to task worktrees

**Array**: `[".env"]`

**Why `.env`**:
- ✅ `.env.example` template exists in repository
- ✅ `.env` is gitignored (confirmed in .gitignore line 8)
- ✅ Contains local secrets (database password, API keys)
- ✅ Required for Laravel to function
- ✅ User's main worktree has customized .env with their credentials

**What `.env` contains** (based on .env.example):
- Database credentials (DB_PASSWORD)
- Stripe API keys
- Paystack API keys
- App environment settings
- Mail configuration
- Cache/queue drivers

**Why copy instead of recreate**:
- User has already configured their main worktree's .env
- Saves time (no manual reconfiguration per worktree)
- Ensures consistency across worktrees
- Preserves user's API keys and secrets

**What's NOT copied** (automatically excluded):
- `node_modules/` - Installed by setup_script
- `vendor/` - Installed by setup_script
- `public/build/` - Generated by Vite
- Build artifacts, cache, logs (regenerated automatically)

## Workflow Automation

### When a new task worktree is created:

1. **Zenflow clones the repository** to a fresh worktree
2. **Runs setup_script**:
   - Installs all dependencies
   - Generates encryption key
   - Sets up database schema
3. **Copies .env** from main worktree
4. **Worktree is ready** for agent to work

### When agent completes work:

1. **Runs verification_script**:
   - Formats code with Pint
   - Runs test suite
2. **If tests pass**: Changes are safe to commit
3. **If tests fail**: Agent sees errors and fixes them

### When starting dev server:

1. **Runs dev_script**:
   - Starts Laravel server on port 8000
2. **User can access**: `http://localhost:8000`

## Troubleshooting

### If setup_script fails:

**Error**: "composer: command not found"  
**Fix**: Install Composer from https://getcomposer.org

**Error**: "npm: command not found"  
**Fix**: Install Node.js from https://nodejs.org

**Error**: "SQLSTATE[HY000] [1045] Access denied"  
**Fix**: Check database credentials in copied .env file

**Error**: "Please provide a valid app key"  
**Fix**: Ensure `php artisan key:generate` ran successfully

### If verification_script fails:

**Error**: "vendor/bin/pint: not found"  
**Fix**: Run `composer install` to install Pint

**Error**: "Class 'Tests\TestCase' not found"  
**Fix**: Run `composer dump-autoload`

### If dev_script fails:

**Error**: "Address already in use"  
**Fix**: Another Laravel server is running on port 8000, use `php artisan serve --port=8001`
